# Bakieva Chat | Вступить в чат

Telegram-бот для продажи 30-дневной подписки на закрытый канал и чат Bakieva Chat.

## Что реализовано

- главное меню строго из 5 пунктов;
- приветствие из ТЗ;
- обязательное принятие оферты, политики конфиденциальности, согласия на обработку данных и условий подписки/возврата;
- Kaspi Pay по ссылке `https://pay.kaspi.kz/pay/8j1mpcx4`;
- доступ **не выдаётся по нажатию «Я оплатил»** — заявка уходит администратору, который подтверждает её только после проверки фактического поступления в Kaspi Pay;
- после подтверждения создаются одноразовые ссылки в закрытый канал и чат;
- подписка на 30 дней;
- напоминание не более чем за 3 дня до окончания;
- автоматический отзыв доступа после окончания;
- кнопка «Вернуться в Bakieva Chat»;
- opt-out из рассылок;
- админ-команды для статистики, выдачи, продления, удаления, цены, рассылок и изменения текстов/материалов без нового деплоя;
- PostgreSQL;
- `/healthz` (процесс и БД) и `/readyz` (готовность poller и Telegram-доступа к платным направлениям).
- Instagram автоответчик по комментариям с отправкой сообщения в Direct;
- публикация Instagram Reels из Telegram-админки: видео → подпись → правило → Direct → публикация → автоматическая привязка Media ID.

## Почему подтверждение Kaspi сейчас ручное

Обычная Kaspi Pay ссылка открывает удалённую оплату, но сама по себе не предоставляет этому боту достоверный webhook о конкретной оплате. Для PDF-фискального чека требуется подтверждение данных на официальной странице Kaspi; если она недоступна, бот не активирует подписку по одному лишь тексту PDF. Поэтому выдавать доступ сразу после кнопки «Я оплатил» небезопасно.

Текущая схема: клиент платит → нажимает «Я оплатил» → администратор сверяет реальное поступление в Kaspi Pay → нажимает «Подтвердить оплату» → бот автоматически выдаёт доступ.

Для полностью автоматического подтверждения нужен отдельный платёжный API/webhook или подключённый эквайринг-провайдер.

## Переменные окружения

Скопируйте `.env.example` и заполните:

- `BOT_TOKEN`
- `DATABASE_URL`
- `ADMIN_IDS` — Telegram ID администраторов через запятую
- `PAID_CHANNEL_ID` — ID закрытого канала (`-1004476014410`, указан владельцем)
- `PAID_CHAT_ID` — необязательная старая привязка чата для существующих функций; недействительное значение отключает только эти функции и не мешает новой выдаче доступа
- `PAID_MAIN_CHAT_ID` — ID группы, куда отправляется приглашение после оплаты (`-1004333394152`, Болталка, по уточнению владельца); также доступна привязка командой `/bind_main_chat` в группе
- `TALK_CHAT_ID` — ID Болталки (`-1004333394152`); существующие приглашения и участники Болталки обрабатываются отдельно от платных персональных ссылок
- `KASPI_MERCHANT_BIN` — 12 цифр БИН получателя для проверки чека
- `OFFER_URL`
- `PRIVACY_URL`
- `DATA_CONSENT_URL`
- `SUBSCRIPTION_TERMS_URL`
- при наличии: `TRIAL_LESSON_URL`, `FREE_CHANNEL_URL`
- для Instagram: `META_APP_ID`, `META_APP_SECRET`, `META_WEBHOOK_VERIFY_TOKEN`, `INSTAGRAM_ACCESS_TOKEN`, `INSTAGRAM_IG_USER_ID`, `META_GRAPH_VERSION`
- для публикации Reels: `PUBLIC_BASE_URL` необязателен на Railway, если доступен `RAILWAY_PUBLIC_DOMAIN`

Kaspi и номер поддержки уже имеют значения по умолчанию:

- `KASPI_PAY_URL=https://pay.kaspi.kz/pay/8j1mpcx4`
- `SUPPORT_PHONE=+77712841932`

## Права бота

Добавьте бота администратором в платный канал и платный чат. Нужны права создавать пригласительные ссылки и удалять участников.

## Запуск

```bash
npm install
npm run build
npm start
```

Для Railway используйте Node.js 22+, PostgreSQL и перечисленные переменные окружения. Оставьте Railway healthcheck на `/healthz`: новый контейнер получает Telegram poller lock после остановки старого. `/readyz` отдельно проверяет DB, poller, scheduler, ID и права бота в канале и Болталке; до получения lock он вернёт 503. Диагностика и повторная выдача доступны в `/admin`; пользователь может запросить свои ссылки командой `/access`. Подробнее: `docs/production-review.md`.

## Администрирование

```text
/admin
/grant TELEGRAM_ID DAYS
/extend TELEGRAM_ID DAYS
/revoke TELEGRAM_ID
/price 5000
/set about новый текст
/set content новый текст
/set trial_url https://...
/set free_channel_url https://...
/broadcast текст рассылки
```

Пользователь должен хотя бы один раз нажать `/start`, прежде чем администратор сможет выдать ему доступ вручную.

В разделе `/admin → Instagram автоответчик → Новый Reels` маркетолог может загрузить видео, указать подпись, выбрать триггер комментариев и текст Direct. После публикации бот получает Instagram Media ID и включает правило автоматически.

При использовании стандартного облачного Telegram Bot API исходный файл Reels должен быть не больше 20 МБ, потому что `getFile` не скачивает более крупные файлы.

## Пробный урок без потери качества

В `/admin → Пробное видео RU/KZ` отправьте первую, затем вторую часть **исходным файлом**: скрепка → Файл → выберите оригинал. Обычное видео из галереи бот отклоняет, сохраняя текущий шаг загрузки: клиент Telegram мог сжать его ещё до получения ботом. Если исходник уже был сжат другим приложением, отправка как файла не восстановит потерянные детали.

Бот хранит Telegram `file_id` и выдаёт тот же документ ученикам. Он не скачивает и не перекодирует эти части, поэтому ограничение на новый multipart upload в 50 МБ не применяется к повторной отправке уже загруженного файла. Обе новые части становятся активными вместе; старый урок доступен до завершения загрузки. PDF и защита содержимого сохраняются. Документ может отображаться как файл, а не как встроенное видео.

Одиночные уроки из базы/seed также загружаются как документы. Для существующих Telegram ID сохранён исходный тип `video`: Telegram не разрешает менять тип при повторной отправке ID. Уже сжатый урок необходимо заменить оригиналом.

`npm run replace:trial:ru` использует `TRIAL_VIDEO_REPLACE_RU_URL` и `DATABASE_URL`: сохраняет полученные байты, имя и MIME без FFmpeg, изменения разрешения или битрейта. После применения миграции `014_trial_video_original.sql` замена одиночного RU-урока и отключение указателей старой пары происходят в одной транзакции. Прямая загрузка этим скриптом ограничена 49 000 000 байт с запасом до лимита Telegram; для более крупного файла используйте загрузку File через админку, не сжимайте оригинал. Seed и защищённый `/internal/trial-upload/:language/:part` предназначены для небольших файлов, загружаемых сервером впервые.

Справочник Telegram: [Sending files](https://core.telegram.org/bots/api#sending-files) и [sendDocument](https://core.telegram.org/bots/api#senddocument).

## Важно про Telegram

Telegram Bot API не позволяет боту принудительно добавить произвольного пользователя в приватный канал или группу. После подтверждённой оплаты бот создаёт персональные одноразовые ссылки на вступление. Это сохраняет требование: получить ссылку на платный чат можно только после подтверждённой оплаты.


## Публикация новостей в Telegram-группы

В действующей админ-панели выберите **📰 Добавить новость**, отправьте текст и при необходимости фото, затем выберите кнопку публикации для всех пользователей или активных подписчиков. Теперь публикация доставляется **не только личными сообщениями**, но и в подключённые группы/каналы. Отчёт приходит администратору после завершения рассылки: для каждой группы показываются название, ID, статус ответа Telegram API, ID опубликованного сообщения, доступная ссылка и текст ошибки, если отправка не состоялась.

Адресаты определяются по привязанным **платному каналу, платному чату и основному платному чату** из настроек админки/Railway. Для дополнительных групп установите `NEWS_TARGET_CHAT_IDS=-1001234567890,-1009876543210` в работающем сервисе Railway (числовые ID через запятую); одинаковые ID исключаются. Бот должен находиться в каждой группе с правом отправки, в каждом канале — с правом публикации. Не следует автоматически направлять новости в публичные чаты, если они не указаны администраторами.

Отправка в группу считается успешной только после возврата идентификатора сообщения Telegram. По каждому адресу сохраняется запись в PostgreSQL (миграция `026_news_group_deliveries.sql`). Повторно посмотреть результат можно через **📚 Материалы → 📊 Отчёт #ID**. Для приватных групп `t.me/c/...` доступен только участникам. Состояние `published` у материала означает, что действие публикации начато, но не гарантирует успешную доставку во все места: фактический статус смотрите в отчёте.

Права на рассылку новостей проверяются существующим механизмом администраторов `ADMIN_IDS`/`ADDITIONAL_ADMIN_IDS`. Публикация в группы не удаляет прежнюю личную рассылку с настройками отписки.


## Видео и подробная статистика публикаций

Рабочая админ-панель:
- **🎬 Загрузить видео** — отдельный видеоматериал; Telegram отправляет его в подключённые группы/каналы и подписчикам выбранной аудитории.
- **📰 Добавить новость** — текст, фото с подписью, обычное видео с подписью либо видео как документ для сохранения исходного качества. Можно сначала отправить текст, затем одним сообщением приложить фото или видео, либо сразу прислать видео с подписью.
- После нажатия «В группы + всем пользователям» или «В группы + подписчикам» бот последовательно отправляет публикацию в привязанные группы/каналы и личные чаты выбранной аудитории.

По итогам администратор получает **два отчёта**: какие группы/каналы приняли публикацию (с ID и ссылками сообщений при наличии) и какие конкретно пользователи получили личное уведомление. Персональный отчёт показывает Telegram ID, известное имя/username, ID сообщения при успехе и причину ошибки при неуспехе. Кнопки **Все / Отправлено / Ошибки** и навигация позволяют листать список без ограничения на число подписчиков. Позднее отчёт открывается через **Материалы → Отчёт #ID**.

Сведения о личных отправках сохраняются в таблице PostgreSQL `content_user_deliveries` (миграция `027_content_user_deliveries.sql`). Для старых публикаций персонального журнала может не быть. Успех означает, что Telegram Bot API принял сообщение и вернул `message_id`; Telegram не предоставляет надёжного подтверждения прочтения конкретным получателем.
