# railway-stable: WhatsApp-профиль и продажи — проверка перед выпуском

## Источник и безопасность
Это **отдельная адаптация** функций PR #72 на существующую рабочую ветку `railway-stable`.
Не заменяйте `railway-stable` содержимым PR #72 из `main`: в рабочей ветке уже есть
Kaspi PDF-чеки, льготные клиенты, AI-шеф, Instagram, новости и миграции 001–028.
Новая миграция: `029_buyer_profiles.sql`, существующие миграции сохранены.

**Никаких автоматических merge/deploy.** Сначала выполните репетицию на копии production
PostgreSQL и отдельном Telegram-сообществе, резервную копию и проверку восстановления.

## Поведение

- Новые покупки: 5 000 ₸ за 30 дней или 25 000 ₸ за 180 дней (6 месяцев).
- Старый льготный клиент сохраняет своё право и календарное расписание платежей.
- Для совместимости с историческими записями внутренний код нового полугодового тарифа
  пока остаётся `five_months`. Срок каждой конкретной покупки хранится в `payments.meta.duration_days`.
  Старые оплаченные 150 дней **не** продлеваются автоматически до 180.
- Оплата для других стран: `https://t.me/tribute/app?startapp=s1a2A`;
  подтверждение Tribute этим ботом не автоматизировано.
- Сервис не выдаёт новое приглашение после подтверждения Kaspi до сохранения WhatsApp
  и согласия на обработку данных. Новые подписки активируются после профиля.
- Возобновить анкету можно через `/start`, `/access` или `/whatsapp`.
- Приглашения требуют рассмотрения администратором Telegram; автоматическое принятие заявок
  остаётся **отключено** по действующему бизнес-правилу `railway-stable`.
  Действующие старые ссылки и ручные добавления администратора могут обходить этот путь.
- WhatsApp номер проверяется **только структурно**: существование учётной записи WhatsApp
  и владение номером не подтверждаются.
- Маркетинговая аудитория создаётся только при отдельном положительном согласии,
  сохранённом в `buyer_profiles.marketing_consent_at`.

## Отчёты и команды

В личном чате Telegram администратора:
- `/sales_today` — полный список подтверждённых покупок сегодня;
- `/sales_yesterday` — вчера;
- `/sales_report 2026-10-22` — выбранный день;
- `/sales_export` — вся история подтверждённых покупок CSV;
- `/contacts_export` — дедуплицированный CSV добровольно согласившихся на маркетинг.

Те же выгрузки доступны кнопками в существующей админ-панели.
Ежедневно после `SALES_REPORT_TIME=09:00` бот отправляет **вчерашний завершённый день**
по часовому поясу `Asia/Almaty`. Доставка отслеживается отдельно для каждого администратора.
При неопределённом сетевом исходе повтор не происходит автоматически во избежание дублей.
Для сверки администратор может вручную запросить отчёт за день.

## Проверки

CI новой ветки должен подтвердить npm ci / typecheck / test / build; тестовый GitHub Actions
PostgreSQL 16 применяет миграции с нуля и проверяет отложенную и повторную активацию.
Автоматические тесты используют подменённые ответы Telegram: живую доставку, права в каналах,
реальные платежи Kaspi/Tribute и миграцию production-данных это **не подтверждает**.

4. Проверить оба новых тарифа, особый цикл старого 5k клиента, повторные оплаты,

   повторную выдачу и невозможность доступа по старым общим ссылкам.
6. Убедиться, что ни один настоящий клиент не получит тестовую рассылку или списание.
7. Только после явного разрешения владельца объединить PR и задеплоить в Railway.
